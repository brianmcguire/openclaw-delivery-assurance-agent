# Delivery Lens Agent Index screenshots

The PNG is an unaltered September 29 capture of the live OpenClaw project-setup card and updated Delivery Lens icon. The three JPEGs are unaltered captures from the completed September 27 OpenClaw pilot. Brian and Jonathan used distinct verified accounts in a shared conversation. The project, milestone, blocker, and recovery plan shown here are explicitly fictional. No chat text or agent response was recreated for this package.

1. [Project setup card and icon](00-project-setup-card-and-icon.png) — Brian opens `DELIVERY FORM` in OpenClaw. The card offers a fictional example, a founder-plus-owner workflow, and fields for project name, customer alias, outcome, and delivery date. The new lens-and-milestones icon appears in the sidebar and agent response. This is a draft form; no new project was saved for this capture.
2. [Owner update and recovery question](01-owner-update-and-recovery-question.jpg) — Jonathan reports missing sandbox access. Delivery Lens records the source, flags the target date, and asks him for a specific recovery action and date. Brian's founder-brief request is visible below.
3. [Owner recovery and founder follow-up](02-owner-recovery-and-founder-followup.jpg) — Jonathan commits to synthetic test data and asks for approval. Delivery Lens records the plan, keeps the blocker open, and notes the question is answered.
4. [Corrected founder brief](03-corrected-founder-brief.jpg) — The later brief shows amber health, the corrected date, source references, the unresolved blocker, and the founder's pending decision.

The captures retain the OpenClaw interface and participant aliases. They contain no credentials, customer names, real customer records, or private network addresses. The historical pilot captures predate the September 29 agent-icon update; the setup-card capture shows the current icon.
