# Two-person pilot for the existing fictional project

This is a prepared sequence, not completed multiplayer evidence. Use the existing fictional project only after confirming it is present. One real founder and a different real project owner must participate from their own accounts.

## Founder and gateway operator

Open the actual shared delivery conversation. Send:

```text
DELIVERY PARTICIPANTS harbor-pilot-20260926
```

Choose Person and pilot-lead, enter the actual HTTPS shared conversation address, then prepare and manually share the packet. The operator first admits the person's own Tailscale identity and adds that login to the isolated gateway trusted-proxy allowlist, following `docs/multiplayer.md`. The card grants no access. Do not share credentials. Confirm the role is still unbound before enrollment.

## Owner, from their own account

```text
DELIVERY WHOAMI
```

Confirm verified and different from the founder. Then:

```text
DELIVERY JOIN harbor-pilot-20260926 pilot-lead
```

Wait for confirmation and inspect the project record. Submit:

```text
DELIVERY UPDATE harbor-pilot-20260926 data-access
FICTIONAL PILOT EXERCISE. I completed the field mapping. Next step is loading the test data. I am blocked because sandbox access has not arrived. My target is 2026-09-30. I need the founder to approve a synthetic dataset if access is still missing tomorrow.
```

Verify that the actual agent records the owner/source and identifies the date threat and blocker. Wait for its recovery question. Then:

```text
DELIVERY RECOVERY harbor-pilot-20260926 data-access
FICTIONAL PILOT EXERCISE. My recovery action is to build a synthetic test dataset by 2026-09-29. I need the founder to approve using synthetic data. The sandbox access blocker is still unresolved.
```

## Founder

Ask: `Give me the founder brief for harbor-pilot-20260926, including evidence, the recovery plan, and the decision needed.` Confirm the agent has not treated the recovery plan as approval or marked the blocker resolved.

## Owner correction

Ask: `Draft a correction for harbor-pilot-20260926 data-access: my target date should be 2026-09-29. Use the actual current revision. Preserve my original update.` Review and send the resulting CORRECT envelope from the owner's own account. Request the updated brief and verify the corrected target, preserved blocker/recovery, and evidence history. Do not assume a revision number.

Capture the seven actual outcomes and both distinguishable identities, with private identity details redacted. If recording later, change the dates together to future dates and check the current record before running this sequence. Do not repeat runs to inflate usage.
